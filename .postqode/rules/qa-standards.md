## Brief overview
- Project-specific QA standards rule aligned to ISTQB and enterprise testing quality expectations.
- Ensure test assets are clear, business-relevant, complete, and execution-ready.

## Standards baseline
- Follow ISTQB-aligned test design and documentation discipline.
- Apply enterprise QA standards for traceability, consistency, and auditability.
- Keep test cases reviewable by both QA and business stakeholders.

## Avoid these quality issues
- Do not create duplicate or overlapping test cases.
- Do not use generic wording that hides business intent.
- Do not keep expected results ambiguous or non-measurable.
- Do not omit preconditions required for reliable execution.
- Do not omit test data needed to reproduce outcomes.

## Preferred test case characteristics
- Use business-oriented scenarios tied to real operational goals.
- Prioritize end-to-end user workflows over isolated technical checks.
- Use realistic data that reflects healthcare and enterprise usage patterns.
- Design tests to be repeatable with consistent outcomes.
- Keep test cases independent so they can run in any order.

## Authoring checklist before finalization
- Verify each test case has explicit preconditions and complete test data.
- Verify expected results are specific, observable, and measurable.
- Verify language is business-readable and free from vague terms.
- Verify no duplicate scenarios exist across the test suite.
- Verify each case can execute independently and repeatedly.
